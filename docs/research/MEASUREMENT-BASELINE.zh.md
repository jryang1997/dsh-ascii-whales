# 历史两条件测量基线（2026-10-25）

历史受控范围内的两条件基线已核实，证据等级为 A。三场景、两条件、每组三轮，共 18 个正式采样单元均从原始文件重新计算。此结论支持 [Issue #4](https://github.com/jryang1997/dsh-ascii-whales/issues/4) 的历史基线交付，不代表整张任务的所有行为验收均由本次数据复核覆盖。

对当前实现的适用性为 D，前提已漂移。被测提交 `b6bf1111656315423f8d921fdd967a02a29d42eb` 尚无 `resourceMode`，省资源条件在当时明确记为未实现。不得把本报告与候选 `10372bd` 拼接计算收益。CPU 仅作三轮描述性记录，资源收益判定保持 `inconclusive`。

[白名单重算数据](measurement-baseline-20261025.json) 保存构建身份、27 项源文件 SHA-256、全部轮次、初始化与预热工作计数、正式工作计数及累计执行毫秒、组中位数与极值范围。报告没有复制原始文本、私有路径、PID、进程清单或原始环境。

## #4 的基线要求与本次范围

Issue 原文要求如下。

> 每单元预热 30 秒、采样 60 秒，至少三轮配对，轮换并记录顺序，初始化与稳定收益分开。提供真实运行的两条件基线及全部轮次，不预填未来省资源档结果。

> 保存配置、事件表、原始数据、异常、每轮结果、中位数及范围；受控页面与真实 DSH 分开说明。测量记录可追溯，后续环境或基线改变必须重新配对，不混用不同构建条件。

本次重算读取 schema 1 的原始清单及 18 个 sample，并核对每单元单独保存的 initialization、warmup 和环境记录。未读取旧 summary 来生成统计。历史工作树的 27 个源文件散列再次与原始清单及既有验证回执一致。构建散列为 `06b484545079b321ecd09f56e00055502bb5f34b18a52c2c4e394be4a31b0585`。

同一天的有窗口尝试因页面隐藏失败，保留作失败证据，未纳入这 18 个有效单元。有效批次为 headless Chrome 的受控文件夹具，使用模拟内容和正式渲染器，不调用真实模型。它不是实际 DSH，也不是可见窗口的指针或视觉验收。

## 三轮描述性统计

每格为中位数 `[最小值, 最大值]`。每组 n=3，计数覆盖约 60 秒正式窗口，不含初始化与预热。CPU 为单核归一化百分比。

| 场景 | 条件 | CPU % | motionStep 次 | draw 次 | wakeup 次 |
| --- | --- | --- | --- | --- | --- |
| idle | off | 0.115 [0.100, 0.251] | 0 [0, 0] | 0 [0, 0] | 0 [0, 0] |
| idle | standard | 44.589 [38.907, 45.316] | 3601 [3600, 3601] | 1600 [1597, 1600] | 9580 [9300, 9598] |
| append | off | 1.126 [0.877, 1.191] | 0 [0, 0] | 0 [0, 0] | 0 [0, 0] |
| append | standard | 54.468 [43.870, 55.841] | 3600 [3600, 3600] | 1600 [1600, 1600] | 9305 [9245, 9569] |
| scroll | off | 6.805 [6.802, 8.328] | 0 [0, 0] | 0 [0, 0] | 0 [0, 0] |
| scroll | standard | 46.613 [44.237, 47.932] | 3600 [3600, 3601] | 1600 [1600, 1600] | 9598 [9582, 9598] |

`motionStep` 是当时实际执行的 1/60 秒物理积分，不是外层调用次数。`draw` 是完成的正式绘制，`wakeup` 是引擎持续动画回调，不是操作系统总唤醒数。OFF 的十个历史注册计数项全部为零，但保留模拟内容与事件负载，因此 OFF 的 Chrome CPU 不必为零。

[重算数据](measurement-baseline-20261025.json) 中 `units` 保留所有工作注册项的次数与累计同步耗时，`groups` 对每项分别计算中位数及范围。包含关系中的执行毫秒不能相加作为总开销。仅凭这些计数不能证明观察器开关对所有动画行为和遮挡规则无影响；该行为验收本次没有重跑。

## 环境与 CPU 归属

环境原件记录 Windows 11 Pro `10.0.26300` x64、Intel Core i5-13490F、16 个逻辑处理器、34183770112 字节物理内存、Chrome `155.0.8059.85`、Node `v24.19.0`。GPU 识别为 AMD Radeon RX 9070 XT，驱动 `32.0.32015.7029`，后端 `ANGLE_D3D11`。CDP 报告 2D Canvas、GPU compositing 与 rasterization 为 enabled；这证明特性状态已记录，不证明 GPU 吞吐或能耗。

CPU 分子重新从 `cpuRaw` 中同一组进程身份和类型的累计 CPU 秒取差并求和。每单元前后进程集合稳定，增量非负。分母采用原件记录的外围 `cpu.elapsedMs`，不替换为页面内 `durationMs`。

```text
单核 CPU 百分比 = CPU 增量秒 × 100000 ÷ elapsedMs
整机归一化百分比 = 单核百分比 ÷ 16
```

范围包括隔离 Chrome 的 browser、renderer、GPU 进程和 utility，以及夹具、CDP 与采样开销。它不是插件独占 CPU，也不是宿主或整台机器的 CPU。GPU 进程的 CPU 秒不能作为 GPU 利用率。没有独立历史瓶颈剖析，本报告不解释哪个资源限制吞吐，不据占用差推导优化收益。

原件记录了启动时 Windows 活动电源方案查询，但操作员 `powerMode` 为 null；方案快照不等于有效电源滑块或实际功率。后台负载未隔离，原始说明允许实现测试在基线期间发生，逐应用干扰未归因。条件轮换只能缓解顺序偏差，不能消除这些混淆变量。物理刷新率未测，初始化 RAF 间隔探测不能代替显示器刷新率。GPU 型号与加速状态也不能补齐这些指标。

## 历史复跑与当前入口的区别

以下仅记录复跑协议，本次未执行测量。精确历史重现可在清理后将历史版本 `b6bf111` 检出到新的隔离副本，使用对应依赖并核对同一构建散列。该版本默认就是两条件，尚无当前的条件选择协议。

```sh
node scripts/measurement.mjs --headless --rounds 3 --warmup-ms 30000 --sample-ms 60000 --out .scratch/historical-two-condition-new
```

当前入口默认三条件。在当前代码上重新取得两条件数据，必须显式选择 `off,standard`，并为本次构建建立一套新配对。

```sh
node scripts/measurement.mjs --headless --conditions off,standard --rounds 3 --warmup-ms 30000 --sample-ms 60000 --out .scratch/current-two-condition-new
```

当前三条件的五轮要求见 [完整协议](../measurement-protocol.zh.md)。新数据只有在同一构建、同一输入和环境协议下重新配对，才可用于后续比较。新 schema 3 公开报告帮助器未用于处理本批旧 schema 1，也未增加兼容 API。
