# ADR 0003：把六票集成分支合并到 1.0.0 主线并在合并构建上重测

状态：已接受（2026-10-28 决策，2026-10-31 完成测量，PR #7）

## 背景

六票在 2026-10-25 于 `integration-whale-improvements-20261025` 上实现并通过受控验收，但用户选择暂停真实宿主验收，代码留在分支。随后主线发布了 0.15.0（工具链迁到 `@jryang1997/dsh-plugin-kit`）和 1.0.0（方格海面、听写聚集与声浪修正），两侧自 0.14 基线起改过同一批文件（38 个重叠文件、23 个冲突）。

可选路线是重写六票实现（丢弃已审查工作）或把分支合并到 1.0.0 之上（保留实现、解决冲突）。已确认的规格要求"在最终集成构建上重新取得三条件数据"，所以旧构建的测量只能作为历史证据。

## 决定

- 以 `main` 合并进集成分支：保留分支的调度器、图例、场景预设、测量埋点，叠加 1.0 的方格海面、听写/声浪、composer 锚点；生成产物由 `pnpm build` / `pnpm preview` 重建，不手工合并。
- 合并后跑完整验证（478 项 / 63 个测试文件），并做第二轮 Standards + Spec 只读审查；Spec 指出的两条证据口径问题（旧报告身份、1.0 增量归属）在文档与测试中修复。
- 在合并构建 `551fa13` 上重跑 45 单元三条件测量、九单元独立剖析与 40 次 React 端点探针；报告与公开 JSON 换成新构建身份，旧的 2026-10-25 数据保留为历史。
- 不合并、安装或发布：以 PR #7 交付，真实宿主验收与升级发布按授权另行处理。

## 后果

- 已审查的六票实现得以保留并落到 1.0.0 代码上；两条并行工作线不再需要维护重复实现。
- 合并解决与绘制时钟修正都发生在测量之前，任何后续源码改动都会使测量身份失效，必须重新配对测量。
- 真实 DSH 指针/键盘/读屏、GPU 与能耗仍未验证；五票保持开放，等可访问的认证宿主通道与安装授权。
